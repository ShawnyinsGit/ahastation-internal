## 1. 产品定义与约束

**AhaStation 的终局定位是「手机替代者」（v1.2 修订，原「AI 专属第二终端」）**：长期目标是用户不再需要手机；短期保留除电话外的完整手机能力集（未来通讯用 VoIP 补，见 D4）。路线是先在生产力场景（24h vibe coding：口袋里用语音驱动 AI 编程 agent，插上外接显示器即变桌面工作站）跑通，再扩展生活场景。它不是游戏机、不是小电脑。软件本体为 AhaMeet（Electron 42 + React 18 + TS，语音会议式 AI 编程协作，集成 Claude Code / OpenCode / Codex 等 agent CLI），软件交互细节见 Phase2 文档。

**v1.1 形态注记**：D2 的手机形态是 Track B（v2）目标；v1 出货形态为 Track A 公模/中度定制 8" 档平板（§6）。「24h 永远在线」的产品话术落到「消息推送靠唤醒后拉取」——suspend 下 agent 不可能继续跑（§2.4 三态），不对用户承诺 suspend 中继续执行。

### 2.1a RK3588 vs RK3588S 封板逻辑（量产优化决策点）

RK3588S 是 RK3588 的成本优化封装变体：**两者 CPU/GPU/NPU 算力与满载功耗相同**，3588S 砍的是部分高速外设与待机功耗/BOM（芯片便宜约 15–25%，量级待 ODM 报价确认）。封板逻辑：

- **验证机阶段两者生态等价**（同一 BSP/主线内核、同一软件栈）。Firefly ROC-RK3588S-PC 即为 RK3588S 代表板——**验证机优先买它，使实测数据直接代表量产芯**（D8 的 Firefly 采购据此锁定 3588S 版本）。
- **一票否决项：USB-C DP Alt Mode 视频输出能力**。RK3588S 典型板/公模的 USB-C 口常只做供电（无 DP Alt Mode 走线），而 D6 桌面模式依赖该能力——封板前必须逐板核实目标 ODM 公模机的 C 口规格书，确认「全功能（PD + DP Alt Mode + 数据）」。
- **封板判定依赖三项实测/报价**（列为开放问题 Q12）：① 目标公模机 C 口 DP 输出核实；② 3588 vs 3588S 待机功耗差实测（§2.4 同方法）；③ ODM 对两颗料的整机报价差。3588S 属量产优化项，不阻塞 v1 工程样机。
- **v1.1 注记**：3588S **不是散热 B 计划**——算力功耗曲线相同，对撞散热红线无帮助（§5.3/R4 已删此选项）；它只做成本与待机功耗的封板决策。

### 2.4 电源管理架构（第一验收项，D10；v1.1 三态重写）

PPP 教训（§2 核心问题 2/3）：suspend 唤醒失败、待机一晚掉电 ~20%（**即均值 ~75mA 量级**）、扩展坞输出 15–30 分钟耗光、原厂 modem 固件 suspend 下漏接电话需刷社区固件。AhaStation 不做电话（D4）绕开漏接电话问题，但 **suspend-resume 成熟度是 SoC/ODM 的第一筛选条件与第一验收项**。

**v1.1 核心修正——三种状态分开定义，分开定指标**（v1 把三者混为一行，且「5mA×8h=5%」算术错误，实为 0.5%；「屏灭跑 agent + ≤5mA」物理上不可能同时成立）：

| 状态 | 定义 | 整机功耗量级 | 指标 |
|---|---|---|---|
| **S-suspend** | suspend-to-**deep**（默认 deep，s2idle 仅作实测对比项——s2idle 在这类平台通常高 5–10 倍功耗）整机睡死 | BSP 内核 deep 开箱通常 20–80mA；RM520N 随主机休眠仍耗 3–6mA | **目标 ≤15–20mA**（S1 实测标定后收紧；对应一晚 8h 掉电 ≤1.6%@10000mAh，v1.2 按 Q2 定案容量换算）；唤醒延迟 ≤2s；1000 次 suspend/resume 循环零失败（rtcwake + 按键注入自动化） |
| **S-在线** | 屏灭，保持 5G DRX 注册/寻呼，可接收推送，agent **不**在后台跑 | 模组 DRX + 整机低速态 | **目标 ≤50mA 均值**（对应一晚 8h 掉电 ≤4%@10000mAh）；唤醒后 **5G 数据恢复 ≤10s**；「网络可用 ≤5s」仅指 WiFi 路径 |
| **S-活跃** | 屏灭但 agent 会话继续跑（A76 簇 + LPDDR5 + 模组活跃） | **1.5–4W（电池轨 400–1000mA）——这不是待机，是续航场景** | 口袋模式连续 agent 会话 **≥2h**（10000mAh 实测；重度 vibe coding 目标 3.5–4.5h，§5.1）；完成时震动/提示音通知（软件 Phase 待承接，客户端细化 §4） |

电源模式策略（软件层，v1.1 修正功耗墙方向）：
- **口袋模式**：默认 S-在线（deep suspend + 5G DRX），用户发起会话进入 S-活跃；「24h 在线」= 唤醒后拉取，不是 suspend 中继续跑。
- **桌面模式**：插显示器 + PD 输入时禁止 suspend；纯电池 + 外接显示为中间档（UI 提示耗电）。
- **低电量兜底**：电量 <10% 时停 TTS 播报转文字气泡、保 ASR（v1.1 修正：旧版「停用 whisper 兜底」在弱网+低电时等于语音全灭）。

## 3. 系统软件栈

### 3.1 内核策略

- **起步**：瑞芯微官方 BSP 内核（5.10，或 ODM 出货配套的 6.1 BSP），拿到 ODM 的内核源码 + 设备树 + 刷机工具链（**写进合同**，ODM 调研 §3 第 3 条）。
- **迁移路线**：功能稳定后逐步向主线内核（mainline）靠拢——RK3588 主线支持是瑞芯微系最活跃的（D10 站社区生态）。迁移判定标准：主线下 suspend-resume、GPU（Panfrost）、MIPI 屏、RM520N 四项全部达标，否则留在 BSP。迁移非 v1 目标，列为 v2 工程项。
- 设备树、内核 config、补丁集全部入库管理（vendor 内核 fork 仓库），避免 ODM「给二进制不给源码」的 PPP 式困境。

### 3.2 发行版选型

**唯一推荐：Ubuntu 24.04 LTS（ARM64）**，理由：

1. PPP 教训 §3：「单发行版 + 单 DE 做深，别多线维护」——只支持一个发行版。
2. 验证机辰想 CX10A、亿道 EM-R16 均有 Ubuntu 出货先例（22.04，ODM 调研 §1.1）；Firefly/ArmSoM 官方 Ubuntu 镜像开箱即用（ODM 调研 §1.2）——样机到量产同一发行版，无迁移成本。
3. Electron / agent CLI 的 linux-arm64 glibc 产物在 Ubuntu 上兼容性证据最充分（tools-support 报告：OpenCode/Claude Code/Codex/Grok Build 官方 aarch64 均为 glibc 或 musl 静态，Ubuntu glibc 直接可跑）。
4. Armbian：作为**社区生态参照与底层适配期的备选**（D10 站社区生态；Firefly/ArmSoM 适配期可用 Armbian 快速起板），但不作为出货系统——多一套用户态 QA 矩阵违背「单发行版做深」。
5. Buildroot：仅用于工厂产测/恢复镜像（最小系统烧录工具），不作产品系统。

（备选记录：若 ODM 公模机仅提供 22.04 镜像，v1 可接受 22.04 起步，24.04 升级列为 v1.x 工程项。待验证：CX10A 的 Ubuntu 是官方镜像还是厂商自适配、是否开放内核源码——ODM 调研 §5。）

### 3.3 显示栈

- Wayland 单栈（PPP 教训：Phosh/Wayland 是最成熟路径的方向）；**合成器 v1.2 Q8 关闭：倾向 labwc**（轻量 wlroots，满足全屏 App + 桌面模式多窗口由 Electron 自管、触控手势、suspend 兼容四项标准；cage  kiosk 模式为备选——设备是单 App 场景时更省内存），S1 实测定案。
- GPU：Mali-G610 → **Panfrost** 开源驱动（主线 Mesa）。BSP 内核上若 Panfrost 不可用则短期用 Mali 二进制 blob + gbm，迁移主线时统一回 Panfrost。Electron 以 `--ozone-platform=wayland` 运行；GPU 加速实测见风险登记表 R2（客户端细化 §3.5-4 已把 ozone/分数缩放/触屏列入实测矩阵，沿用）。
- 内置屏 1080p + 外接 DP Alt Mode 双屏：内置屏切陪伴屏（D6），外接屏为主显示。显示模式切换守护进程监听 DRM hotplug 事件，触发 D6 状态机（软件 Phase 8）。

### 3.4 音频栈

- **PipeWire 单栈**（不做 PulseAudio/JACK 混叠）。PPP 教训 §2 核心问题 1：PipeWire 路由通话音频频繁失败——那是 telephony 路由问题，D4 不碰电话，整体绕开；但教训保留：音频路由策略必须简单、单一栈。
- 路由优先级（从高到低）：会议语音链路（mic → 云端 ASR；TTS → 扬声器/耳机）> 系统提示音 > 媒体。双麦阵列的降噪在前端做，**AEC 归一 Chromium AEC3**（不叠 webRTC APM/SpeexDSP 双 AEC，客户端细化 §3.2），不依赖 modem 侧任何音频通路（无 modem 音频，D4）。
- **v1.1 补**：桌面模式下外接显示器的 DP/HDMI 音频输出路由（显示器扬声器/音频回传）列入 PipeWire 路由策略与 Phase 6c 实测。
- TTS：Linux Chromium `speechSynthesis` 通常零语音（客户端细化 §3.2 已识别），主路径为云端 TTS（5G 在线，§4.4）；本机仅提示音；**离线兜底 TTS 要做（piper 类，优先级 P2，v1.2 Q6 关闭）**——见 §4.3a。

### 3.5 5G 数据链路

- 栈：ModemManager + NetworkManager；RM520N-GL 走 QMI 或 MBIM（以 ModemManager 对该模组的默认驱动为准，待验证——需在 Firefly 开发板 + M.2 转接板上先行验证，ODM 调研 §2 路径 2 已列此做法）。
- 网络管理策略：
  - **5G / WiFi 自动切换**：WiFi 可用且质量达标走 WiFi（省流量），否则 5G；切换对应用层会话的影响要实测（云端 ASR 流断线重连，复用断线 resync 设计）。
  - **弱网降级**（v1.2 客户端细化已修顺序，沿用）：TTS 降文字气泡 → agent 心跳/事件降频 → ASR 最后；触发用 ASR/TTS 延迟滑动窗口指标。
  - 永远在线（D4）：suspend 策略见 §2.4 三态（S-在线 为默认口袋态）。
- 无 VoLTE、无 SMS 路由、无电话号码——SIM 为纯数据卡；**进网许可仍默认必做**（§7，v1.1 修正）。

### 3.6 刷机与恢复

D10：刷机恢复路径开箱可用是开发者设备生命线。

- **SD 卡兜底启动**：BootROM 支持 SD 优先启动（RK3588 原生能力），恢复卡插入即可重刷整机，永远砖不了。
- **rkdeveloptool / maskrom 恢复**：USB-C 进 maskrom 模式用瑞芯微官方工具线刷，工厂与售后共用同一流程。
- **A/B 分区 OTA**：系统双分区 + 回滚；**v1.2 Q9 关闭：倾向 RAUC**（A/B + 验签生态成熟），S2 阶段验证定案；用户态 OTA 失败自动回退；data 分区独立。**OTA 镜像强制验签为不可妥协红线**（§3.7）。
- 镜像发布物：完整线刷包 + SD 恢复卡镜像 + OTA 增量包，三种同时发布。

### 3.7 设备安全（v1.1 新增章——此前全文为零，是产品级缺口）

这是一台装兜里、存着用户全部代码仓库和各 agent API keys 的设备。丢一台 = 泄露全部代码 + 云端密钥。最低四件：

1. **锁屏**：PIN/图形，与 suspend 唤醒联动；连续错误锁定。
2. **数据加密**：per-user fscrypt（v1 底线）或 LUKS 全盘（v2 目标）；密钥与锁屏凭据绑定，**恢复出厂 = 销毁密钥**。
3. **安全启动**：RK3588 安全启动链（BL31/uboot 验签），防刷入篡改系统。
4. **OTA 验签**：RAUC（v1.2 Q9 倾向）/swupdate 镜像强制验签——不验签的 OTA 通道本身就是 RCE 通道。
5. **摄像头可控（v1.2 Q1 联动）**：前后双摄的物理指示灯（硬件联动，软件不可绕过为目标）+ 系统级权限总开关。

关联流程：返厂/维修设备的用户数据标准擦除动作；工程样机流转登记（见 §6 备注）。

### 4.3a 离线兜底 TTS：piper 类（v1.2 Q6 关闭，优先级 P2）

- **要做**：离线场景下 ASR（whisper 兜底）可用而 TTS 失声，则会议循环断一半——离线兜底必须成对。
- 选型：piper 类轻量本地 TTS（极小的模型与 CPU 开销），跟随 whisper.cpp 的集成一起做（同一 CI 自编译/打包管线，同一「不可用时明确降级」UI 策略）。
- 优先级 P2：不阻塞 v1 出货，v1.x 落地；低电量策略（§2.4）下本机 TTS 亦可作为云端 TTS 的省电替代。

### 4.4 云端 ASR/LLM（在线主路径；v1.2 Q5 关闭）

- 要求：流式 ASR（WebSocket/gRPC 流）、中文优先、首字延迟 <500ms（5G 条件下）、支持会话内取消（barge-in 为客户端属性，客户端细化 §3.2）；TTS 流式、延迟 <1s。**默认实现为流式 provider，OpenAI whisper-1 批量 API 仅免费兜底**（v1.1 裁决：非流式，物理上达不到延迟与打断指标）。
- **供应商定案（v1.2）**：
  - **provider 抽象层为架构必备**（ASR/TTS 各自可插拔，避免与单一供应商绑定）；
  - **首发默认：火山引擎**（流式 ASR + TTS 一家覆盖、中文延迟与性价比头部、匹配大陆首批用户）；
  - 海外版可切 Deepgram / ElevenLabs；
  - 支持用户填自己的 API key（BYOK）。
- **成本模式（同时是商业模式定义）**：首年语音服务随设备赠送；次年起设备订阅含基础额度；超出部分用户用自己的 key。与 Q13 流量策略同哲学：「送体验，不卖资源」。
- 弱网降级策略见 §3.5；断网兜底见 §4.3（ASR）与 §4.3a（TTS）。

## 5. 结构与人机工程

### 5.1 加厚机身换电池：v1.2 定案 10000mAh（Q2 关闭）

**决策（v1.2）**：Track B 电池定案 **10000mAh**。理由：反向充电当充电宝需要容量冗余（D2 原话「可以厚一些」）；目标续航 **重度 vibe coding 3.5–4.5h / 混合使用 8h+**；可接受代价 **14–16mm 厚度、280–320g 重量**。关联锁定：① 反向充电 PD 输出 **18W 起谈、目标 22.5W**；② **电池可更换设计为结构硬约束**（可拆后盖，欧盟 2027 电池法；售后/备件联动 §7 与附录 13）。

锂聚合物电池能量密度按 ~250Wh/kg、体积能量密度 ~600Wh/L 量级估算（定案前框算，留档）：

| 方案 | 电池容量 | 电芯厚度贡献（~6.5–7" footprint，约 140×70mm） | 整机厚度量级 | 整机重量量级 | 结论 |
|---|---|---|---|---|---|
| 常规 | 5000mAh | ~4–5mm | ~9–10mm | ~200–220g | 否（充电宝冗余不足） |
| 加厚 A | 8000mAh | ~6–7mm | ~11–12mm | ~240–260g | 否（v1.2 被 10000mAh 取代） |
| **加厚 B** | **10000mAh** | ~8–9mm | **~14–16mm**（含可拆后盖结构增量） | **~280–320g** | **选定（v1.2）** |

Track A（8" 公模）电池随公模，不受此表约束。

### 5.2 侧边按键功能映射建议（GPIO，3–4 键）

| 键 | 建议功能 | 说明 |
|---|---|---|
| K1（大键，食指位） | 按住 = 临时开麦（对齐桌面空格语义） | **默认连续对话模式**（v1.1 修正，与桌面一致不开倒车到 PTT）；模式状态底栏常显 + 切换提示音；suspend 下按 K1 = 仅唤醒，松开再按才说话（防吞键/误录） |
| K2 | 打断键：一键打断当前 TTS/agent 输出 | 对应会议「打断」底栏键（客户端细化 §3.3） |
| K3 | 电源键：短按亮灭屏、长按开关机、双击打开会议 | 兼 suspend 唤醒源（§2.4 验收；BSP 设备树 GPIO wake 配置列入 checklist） |
| K4（可选） | 自定义：默认切陪伴屏/最近会话 | 可软件重映射 |

全部按键事件经 GPIO → input 子系统 → AhaMeet 全局快捷键层（uinput 虚拟键盘或 native globalShortcut，**注入通道列为软件 Phase 6c 工作项**，v1.1 补）；overlay 打开时语音默认发会议，长按员工 chip 锁定对讲该员工（客户端细化 §3.3）。

### 5.3 散热（无风扇被动散热；v1.1 温度分区修正）

RK3588 满载整机功耗 10W 级。**v1.1 温度口径分区**（v1 的 ≤42°C 与红线 ≤45°C 无分区必扯皮）：

- **握持区**（持续皮肤接触）：≤42–43°C（参考 IEC 62368 可触及表面温度限值塑料件档位；口袋贴身 35°C+ 场景是低温烫伤风险最高处）；
- **背板中心热点**（短时触碰）：≤45–48°C；
- 所有温度指标注明环温条件：**30°C 环境舱验收**（实验室 25°C 覆盖不到夏季贴身）。

设计要点：

- SoC 背面大面积均热：铜箔/石墨片 + 中框铝合金导热路径，把热量摊到整机背板；5G 模组与 PMIC 热源远离手持握持区布局。
- **DVFS 三档功耗墙（v1.1 修正方向）**：**口袋模式最严**（贴身 + 无对流，最差散热场景）/ 电池+外接显示中间 / PD+桌面模式最宽（插电、不手持）。
- 降频曲线与「长时间满载 agent 会话」场景实测挂钩（风险登记表 R4）；CX10A 阶段先测出持续负载下的频率-温度曲线作为设计输入（定位见 §6，不裁决手机形态）。
- **B 计划（v1.1 修正，删 3588S——算力功耗曲线相同无帮助）**：① 加厚均热/结构导热；② 锁功耗墙 4–5W 接受吞吐下降（降性能定位）；③ 加风扇（牺牲无风扇卖点，最后手段）。

### 5.4 外接显示器硬件路径（D6）

- 单 USB-C 口同时承担：DP Alt Mode 视频输出（RK3588 DP 1.4 能力）+ PD3.0 输入充电 + USB 数据。用户插一线（或一线到显示器/扩展坞）即进入桌面模式并充电。
- DP Alt Mode 与 PD 的共接需要 Type-C 控制器（如 TPS6598x 类或瑞芯微参考设计配套），要求 ODM 在公模机上确认该口为「全功能」而非仅充电/仅数据——**询价三要素之外的第四确认项**。
- 纯电池供电带外接显示器为允许场景（续航按 §2.4 S-活跃档实测），但 UI 提示耗电。
- 目标：外接 1080p/2K 显示器 60Hz 稳定输出；4K 列为待验证项（被动散热下的 GPU/内存带宽压力）。
- 外接显示器的 DP/HDMI 音频输出路由见 §3.4（v1.1 补）。

### 5.5 蜂窝天线（v1.1 新增小节——此前只出现在成本备注，实为结构硬约束）

RM520N 需要主集 + 分集/MIMO 共 **4 根蜂窝天线**。Track B（6.5–7" 金属中框小机身 + 10000mAh 大电池占满内部面积 + 石墨/铜箔均热层）的天线净空是全新 ID 里最硬的结构约束之一，直接决定 SRRC 余量：

- Track A 优先沿用公模机已验证天线（S2 询价索取目标公模的**天线测试报告**）。
- 风险登记表新增条目（§8 R10）。

**S1 压测周验收标准（v1.1 修正：红线改吞吐指标，定位降级）**

CX10A 到货**第一周固定为压测周**，先于任何功能适配执行：

- **负载定义**：满软件栈——Electron 会议 UI + 3 个 agent 会话 + 云端 ASR 流式 + 屏幕最高亮度 + **陪伴屏常亮**（v1.1 纳入），**连续 30 分钟**。
- **红线（v1.1 改为吞吐 + 温度分区）**：① agent 任务完成速率不低于空闲基线的 70%、会议 UI 帧率 ≥30fps、ASR 链路不中断；② 表面温度按 §5.3 分区（握持区 ≤42–43°C 持续、热点 ≤45–48°C 短时），**30°C 环温舱复测**；频率曲线只作诊断数据不作红线（调校良好的稳定低频优于剧烈波动）。
- **最差工况用例（v1.1 新增）**：PD 充电中满载、5G 弱信号（PA 多发 2–3W）、环温 30°C+、口袋内无对流（织物覆盖模拟）——实验室 25°C + 满亮屏覆盖不到贴身口袋这个最危险场景。
- **时序约束修正（v1.1）**：S1 数据作为 **S3 EVT 散热设计输入**与 ODM 谈判技术谈资；「撞线即推翻无风扇」的裁决**不在 CX10A 做出，在 EVT 整机**——EVT 撞线 = 加厚 / 锁功耗墙 / 加风扇三选一（§5.3 B 计划）。
- 执行细则见 `docs/checklist-s1-bringup.md` §4。

**S2 询价四要素**（ODM 调研 §2 三点 + §5.4）：
1. 5G 模组兼容性：M.2 B-key + SIM 对 RM520N 的实际兼容（供电、天线接口），索取 5G 选配规格书与**天线测试报告**（v1.1）；
2. 内核源码：Ubuntu 镜像是官方还是自适配、是否开放内核源码 + 设备树 + 刷机工具链（写进合同）；
3. MOQ 与定制梯度：公模轻定制（2–4 周、MOQ 几十–500 台）→ 中度定制（45–90 天、MOQ 500–2000）→ 全新 ID（4–8 个月、MOQ 1000+）的报价梯度；
4. USB-C 全功能口（§5.4）。

**工程样机管理（v1.1 新增）**：S1/S2/EVT 各阶段工程机含未发布代码、API keys、modem 证书——流转登记 + 回收/销毁流程 + 重刷标准镜像 + 安全擦除（与 §3.7 联动）。
